# Backend Test Task

## Введение

В изначальной реализации приложения логи событий записываются напрямую в ClickHouse, что приводит к следующим проблемам:

- Потеря событий при сбое веб-воркера.
- Ошибки на UI из-за сетевых сбоев при записи в ClickHouse.
- Перегрузка ClickHouse из-за большого количества построчных записей.

Цель изменений — реализовать механизм записи логов через транзакционный outbox, чтобы устранить указанные проблемы и улучшить UX.

## Основные изменения

### 1. Модель Outbox

- Добавлена модель и приложение для реализации схемы транзакционного outbox.
- Логи теперь сначала сохраняются в PostgreSQL, а затем асинхронно отправляются в ClickHouse.

### 2. Изменение use_case

- Логика работы use_case изменена для интеграции с новой схемой записи логов.

### 3. Задачи Celery

- Реализованы задачи Celery для пакетной обработки логов и их записи в ClickHouse.
- Добавлена задача для очистки обработанных записей из базы данных.

### 4. Тестирование

- Обновлены существующие тесты для работы с новой логикой use_case.
- Добавлены новые тесты для проверки задач Celery.

### 5. Инфраструктура

- Добавлены контейнеры для Celery и Celery Beat.
- Обновлен файл `.env.ci` для корректной работы с Redis.
- Обновлен `requirements.txt` для поддержки новых библиотек.
- Добавлены новые файлы для распределения логики и лучшей читаемости кода.

### 6. Логика работы

#### До изменений

Django (Бизнес-логика)
│
▼
ClickHouse
▲
│
[Проблемы]
│
├───> Потеря событий (веб-воркер умирает)
├───> Сетевые ошибки → Ошибки на UI → Плохой UX
└───> Много построчных записей → Перегрузка ClickHouse

#### После изменений

Django (Бизнес-логика)
│
▼
База данных (Логи)
│
▼
Celery
│
├───> Забирает логи пачкой → Записывает в ClickHouse
│
└───> Очищает БД от обработанных записей
│
▼
[Обработка ошибок]
│
├───> Ошибка записи в ClickHouse → Откат изменений
└───> Успешная запись → Удаление логов из БД

## Заключение

Реализованный механизм транзакционного outbox устраняет проблемы потери событий,
улучшает UX и снижает нагрузку на ClickHouse. Все изменения интегрированы в существующую архитектуру,
а тесты обеспечивают стабильность работы системы.
